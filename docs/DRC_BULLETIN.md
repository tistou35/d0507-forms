# ส่งประกาศให้เซ็นรับทราบ — AeroFBO → DRC

สัญญาข้อมูลระหว่างระบบเอกสาร (`indyzz.com/aerofbo`) กับใบรับเอกสาร
**D-0507-DRC-001 · Document Receipt**

**สถานะ:** ตกลงแล้ว 23 AUG 2026 · ฝั่ง AeroFBO ยังไม่ได้ทำปุ่มส่ง

---

## ปัญหาที่แก้

AeroFBO ส่งประกาศแล้วแจ้งทางไลน์ เปิดลิงก์แล้วระบบจับได้ว่าใครเปิดดู
แต่ **"เปิดดู" ไม่เท่ากับ "รับทราบ"** — ไม่มีลายเซ็น ไม่มีหลักฐานว่าอ่านแล้วเข้าใจ
DRC ทำหน้าที่นั้น

## ทำไมต้อง prefill ไม่ใช่วางลิงก์เปล่า

ถ้าให้ผู้รับพิมพ์ชื่อเอกสารเอง จะพิมพ์ไม่ตรงกัน แล้วจับคู่ไม่ได้ว่าใครรับทราบฉบับไหน
ให้ระบบต้นทางเติมมาให้ เหลือให้ผู้รับแค่ตรวจว่าตรงกับที่ได้รับจริงแล้วเซ็น

## รูปแบบลิงก์

```
https://tistou35.github.io/d0507-forms/fill/?c=DRC&p=<base64url(JSON)>
```

```js
const p = btoa(String.fromCharCode(...new TextEncoder().encode(JSON.stringify(o))))
            .replace(/\+/g,'-').replace(/\//g,'_');
```

⚠️ ค่าทั้งหมดต้องอยู่ **ข้างใน `p`** — หน้ากรอกอ่าน query param แค่ `c` กับ `p`
`?ref=...` ระดับบนสุดถูกทิ้งเงียบ (ถ้าส่งมาจะขึ้นคำเตือนใน console)

## คีย์ที่ส่งได้ตอนนี้

| คีย์ | ชนิด | ค่า |
|---|---|---|
| `docs` | table | รายการเอกสาร — แถวละ `{title, code, rev, eff}` · **ตอนนี้ใช้แค่ `title`** |
| `rcvName` | text | ชื่อผู้รับ ถ้าระบบต้นทางรู้อยู่แล้ว |
| `rcvRole` | text | ตำแหน่ง |
| `issBy` | text | ผู้ออกประกาศ |
| `issDate` | date | `YYYY-MM-DD` |
| `ref` | passthrough | เลขที่ประกาศฝั่ง AeroFBO — **ยังไม่ใช้ เตรียมที่ไว้แล้ว** |

ตัวอย่างที่ใช้ได้วันนี้

```js
const o = { docs: [{ title: "ประกาศแนวปฏิบัติการเติมน้ำมัน ฉบับที่ 3" }] };
```

พอฝั่ง AeroFBO พร้อมส่งเลขที่ ก็เพิ่ม `ref` เข้าไปในก้อนเดียวกันได้เลย
ฝั่งนี้รับไว้แล้วโดยไม่ต้องแก้อะไร ค่าจะไปโผล่ในชีต `DRC — Records` แถวเดียวกับข้อมูลอื่น
